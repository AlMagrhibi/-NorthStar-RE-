# Client compatibility and reconstruction

**Mandatory shared gate:** Read `../environment-discovery-setup/SKILL.md`, `../../references/evidence-contract.md`, and `references/operational-reference.md` before work. Verify required tools, install only approved missing dependencies, and use actual target evidence rather than a fixed client or version.

Read environment-discovery-setup, then binary preflight and the appropriate tool skills. Read references/compatibility-playbook.md. Establish the actual client identity, architecture, file hashes, declared version if observable, input/output behavior, dependencies, protocol authorization, target language and build system. Unknown means unknown. Never assume a specific game or version. Use clean-room behavioral specifications, fixtures and tests; do not copy proprietary code or bypass protection, anti-cheat, access controls or licensing. Distinguish observed bytes/IL/addresses from hypotheses. Identify input format, boundary conditions, encoding, structure alignment, ABI, external dependencies, error behavior and expected outputs. If rendering is relevant, document coordinate convention, texture orientation, transform order, blending and depth from evidence. If a format is undocumented, do not invent offsets. Compare authorized reference behavior with a minimal independent implementation. Build only trusted source with Visual Studio or the discovered project toolchain. Report exact hashes, tools, environment, test vectors, limitations, unresolved compatibility and regression results.
