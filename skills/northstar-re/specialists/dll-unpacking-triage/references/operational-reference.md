# DLL understanding and recovery decision reference
Start with hash, PE headers, machine, sections, import/export tables, CLR metadata, signatures and resources. A high-entropy section may be compressed, encrypted or ordinary data. Detect It Easy and PE-bear provide independent static clues, not proof. DUMPBIN `/HEADERS`, `/IMPORTS`, `/EXPORTS` on trusted fixtures validates architecture and interfaces; compare findings with ILSpy or Ghidra as indicated. Do not load the DLL or invoke exports merely to identify it. Inspect documented container and vendor format. Distinguish: native instructions (Ghidra), managed IL (ILSpy), mixed (both), public compression (documented extraction), encrypted owner data (documented algorithm/key/nonce/tag, authenticate before acceptance), obfuscated or protected code (record limitation; use owner-provided unprotected build/symbols). For legitimate decryption, use standard vetted crypto APIs and known-answer tests, never log keys or guess secrets. Never bypass licensing, DRM, anti-cheat or access controls. For unknown protection request owner-provided debug build, PDB or format documentation. Do not attempt execution or automated bypass. On derived copies record input/output hashes, source, validation and rerun classification. Output a DLL map: exports, imports, dependencies, CLR type/method inventory or native functions, resources, architecture, evidence, unknowns.
