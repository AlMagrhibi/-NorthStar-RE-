Never execute unknown DLLs. For trusted source-only work route directly to Visual Studio after environment gate.
3. Route by evidence: packed/encrypted/obfuscated/unknown -> `dll-unpacking-triage`; managed IL -> `ilspy-dotnet-decompilation`; native PE/NativeAOT/firmware -> `ghidra-native-analysis`; mixed -> both. Read each specialist's references and `references/tool-selection.md`. Legitimate documented recovery of owned data with supplied keys only; no universal decryptor or protection bypass. Repeat preflight on derived artifacts.
4. For any client directory, activate `client-data-discovery` first. Route uncertain binary structures to `binary-format-engineering`, suspected encoding/compression/authorized key-based recovery to `data-cryptography-analysis`, archives to `game-archive-analysis`, media/maps/models to `game-assets-analysis`. Activate `conquer-domain-knowledge` only on user request or evidence of Conquer, never assume a fixed release. For multiple snapshots use `cross-version-analysis`; for missing parsers/converters use `custom-tool-development` with `visual-studio-dev`. Each specialist reads its usage reference and the central tool catalog. Keep a versioned evidence ledger and schema/fixture knowledge in the authorized workspace; do not persist secrets.
5. For authorized server tasks, identify service boundaries and language/build evidence before routing: login/authentication -> `account-server-engineering`; packet/schema analysis -> `network-protocol-analysis`; secure transport and legitimate test-key cryptography -> `network-cryptography`; world/game logic -> `game-server-engineering`; persistence/migrations -> `database-engineering`; multi-service compatibility -> `client-server-interoperability`. Read `references/server-workflow.md`. Combine with `visual-studio-dev` and existing analysis specialists as needed. Local synthetic identities, isolated services, no third-party access, credential capture, ticket forgery or weakening authentication. Do not assume account server language, client release, ports, database or service names.
6. Combine independently corroborated findings: identity, PE/CLR type, exports/imports, resources, dependencies, observed functions/classes, format, transformation hypotheses, evidence and limitations. Verify with trusted fixtures. Do not conflate decompilation, decompression and decryption. Produce environment, preflight and analysis reports. Report unknowns rather than guessing.
