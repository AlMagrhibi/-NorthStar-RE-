# Installation and upgrade
1. Close the agent before installing. Extract ZIP to trusted disk. Verify SHA256SUMS against the provided package; this is integrity, not signer authenticity.
2. On a machine with Rust MSVC and Visual Studio C++ Build Tools, run `Install.cmd`. If crates aren't cached, explicitly permit network with `Install.cmd -AllowDependencyDownload`. No silent download/elevation. For a specific root use `-SkillRoot "C:\Users\YOU\.agents\skills"`; only use a path confirmed by the actual host. A fresh install prompts for it if discovery is ambiguous. `-NonInteractive` means you have approved this operation and supplied the real path. No automatic agent config change.
3. Source goes to `%LOCALAPPDATA%\NorthStarRE\releases\v11-<id>`; generated binary is `engine\bin\nsre.exe` inside that version. Installer runs Cargo tests and release build before switching the master. No Cargo installed? installer fails with instructions and does not activate. First lockfile is generated locally; review it. No signed precompiled binary shipped in this source ZIP. The installer also supports a trusted, manifest-verified future package with `engine/bin/nsre.exe`, after version and doctor smoke checks.
4. Reload skills; run `/skill:northstar-re` only if that host exposes the command. In another host select the skill by its supported mechanism. Ask it to run the absolute `nsre doctor` and `nsre resume --project <existing>`.
5. `Update.cmd` from a newer package preserves previous release and skill backup. `Backup.cmd` copies registered skill + registration; central source/release remains separate. `Uninstall.cmd` unregisters by moving the owned skill and registration into backup, not deleting project data. `Doctor.cmd` checks current executable; `Build-Engine.cmd` builds another version directory without registering it. Do not launch concurrent installers. Installation rollback is best-effort for regular errors, not an atomic multi-directory power-loss transaction. In a crash, review backups and registration manually. Never overwrite unrelated directories.
6. Projects retain `.northstar` and source. Legacy project files remain untouched; new session/memory records stored in SQLite. Manual reviewed migration is still needed for old knowledge JSON. No database snapshot of live application DB implied by checkpoint; use its native backup mechanism first.

MCP optional, legacy stdio 2025-11-25 candidate, config example (replace with verified absolute paths):
```json
{"mcpServers":{"northstar-re":{"command":"C:/Users/YOU/AppData/Local/NorthStarRE/releases/v11-ID/engine/bin/nsre.exe","args":["mcp","--project","C:/work/project"]}}}
```
Do not assume the host accepts that config schema. CLI invocation is primary. MCP exposes only read-only doctor/status; no arbitrary commands, network listener, or mutations. Test handshake and host compatibility first.
